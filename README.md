# yandex-tracker-mcp

MCP сервер на Go, который предоставляет операции
[Яндекс Трекера](https://tracker.yandex.ru/) как для
MCP-клиентов (Claude Code, Codex и т.д.).

## Инструменты (tools)

Полный список — 180 тулов. Glob-паттернами в `YANDEX_TRACKER_TOOLS` можно
сократить набор, который видит клиент (подробнее — в разделе
[Конфигурация](#конфигурация)); колонка «По умолчанию» показывает, какие
тулы включены без дополнительной настройки.

Колонка «Тип» — это то же деление, что используется `YANDEX_TRACKER_TOOLS_MODE`
(см. [Конфигурация](#конфигурация)):

- **чтение** — не изменяет данные Трекера (`ReadOnlyHint`).
- **изменение** — изменяет данные, но не удаляет и не затрагивает много
  объектов сразу (создание, правка, переход и т.п.).
- **деструктив** — удаляет данные или массово действует на многих объектах
  (`DestructiveHint`); доступно только в режиме `full`.

## Конфигурация

Сервер общается с клиентом через stdio и настраивается переменными
окружения. Их можно задать напрямую в окружении процесса либо положить в
файл `.env` в корне `yandex-tracker-mcp` — он подхватывается автоматически
при старте (если файла нет, это не ошибка). Пример со всеми переменными —
в [`.env.example`](.env.example).

Самый быстрый способ — интерактивный wizard: он спросит токен и ID
организации, запишет `.env`, а затем предложит сразу зарегистрировать сервер
в Claude Code или Codex (или покажет JSON-сниппет для других клиентов):

```sh
./yandex-tracker-mcp init
```

Тот же выбор доступен и без wizard'а — отдельными командами. Каждая из
них, если обязательные переменные ещё не заполнены, сама предложит
запустить `init`:

```sh
./yandex-tracker-mcp install-claude   # зарегистрировать в Claude Code
./yandex-tracker-mcp install-codex    # зарегистрировать в Codex
./yandex-tracker-mcp snippet          # вывести JSON-сниппет для других клиентов
```

Переменные:

- `YANDEX_TRACKER_TOKEN` (обязательна) — OAuth-токен с доступом к Tracker
  API. См. [доступ к API](https://yandex.ru/support/tracker/ru/concepts/access).
- `YANDEX_TRACKER_ORG_ID` — ID организации, отправляется в заголовке
  `X-Org-ID` (организации Яндекс 360).
- `YANDEX_TRACKER_CLOUD_ORG_ID` — ID организации, отправляется в заголовке
  `X-Cloud-Org-ID` (организации Yandex Cloud). Должна быть задана ровно одна
  из `YANDEX_TRACKER_ORG_ID` / `YANDEX_TRACKER_CLOUD_ORG_ID`.
- `YANDEX_TRACKER_BASE_URL` — переопределяет базовый URL API (по умолчанию
  `https://api.tracker.yandex.net`).
- `YANDEX_TRACKER_TOOLS_MODE` — какие тулы регистрируются на старте
  (по умолчанию `read-write`):
  - `read-only` — только тулы, помечённые как `ReadOnlyHint` (чтение, без
    каких-либо изменений).
  - `read-write` (по умолчанию) — все тулы, кроме помеченных
    `DestructiveHint` (удаление и массовые/bulk-операции).
  - `full` — все тулы без ограничений, включая деструктивные и bulk.
- `YANDEX_TRACKER_TOOLS` — список glob-паттернов через запятую (как в
  `path.Match`: точное имя или имя с `*`); тул регистрируется, только если
  подходит хотя бы под один из них. По умолчанию — 56 тулов из 180: задачи
  (`issue_*`), доски и спринты (`board*`, `sprint_*`), пользователи и
  трудозатраты (`user*`, `worklog_*`), а по очередям, компонентам и
  глобальным полям — только чтение (`queue_get`, `queues_list`,
  `component_list`, `field_list` и т.п.), без admin-операций вроде
  `queue_create`/`component_edit`/`field_category_create` (какие именно тулы
  входят в дефолт — колонка «По умолчанию» в
  [таблице выше](#инструменты-tools)). `*` снимает это ограничение и включает
  все тулы, разрешённые режимом — пустое значение для этого не подходит:
  пустая переменная окружения откатывается на тот же дефолт (особенность
  `caarlos0/env`), а не отключает фильтр. Паттерн с синтаксической ошибкой
  (например, непарный `[`) — ошибка валидации при старте; паттерн, который
  не совпал ни с одним тулом (например, опечатка `isue_*`) — предупреждение
  в stderr при регистрации, сервер всё равно запустится.

Отключённые режимом или списком тулы не просто помечаются — они вообще не
регистрируются на MCP-сервере и не видны клиенту в списке доступных
инструментов.

## Установка

Готовые бинарники для Linux, macOS и Windows (amd64 и arm64) лежат в
[Releases](https://github.com/hoggerty/mcp-yandex-tracker/releases/latest).
Скачайте архив под свою платформу, распакуйте и при желании сверьте контрольную
сумму с `checksums.txt`.

На macOS скачанный бинарник может блокироваться Gatekeeper'ом; снять карантин:

```sh
xattr -d com.apple.quarantine ./yandex-tracker-mcp
```

Сборка из исходников описана в [`dev/BUILD.md`](dev/BUILD.md).

## Запуск

Бинарник — это CLI на [cobra](https://github.com/spf13/cobra) с подкомандой
`server`. Без аргументов запускается `server` по умолчанию:

```sh
./yandex-tracker-mcp          # то же самое, что ./yandex-tracker-mcp server
./yandex-tracker-mcp --help
```

## Пример конфигурации клиента

```json
{
  "mcpServers": {
    "yandex-tracker": {
      "command": "/absolute/path/to/yandex-tracker-mcp",
      "env": {
        "YANDEX_TRACKER_TOKEN": "y0_...",
        "YANDEX_TRACKER_ORG_ID": "1234567"
      }
    }
  }
}
```

### Claude Code

```sh
claude mcp add -s user \
  -e YANDEX_TRACKER_TOKEN=y0_... \
  -e YANDEX_TRACKER_ORG_ID=1234567 \
  --transport stdio yandex-tracker /absolute/path/to/yandex-tracker-mcp
```
